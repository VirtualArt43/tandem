From: Processes and threads: the memory picture
A method declares a local int total = 0, adds 1 to it 100 times in a loop, and returns it. Fifty threads call the method at the same moment. What can each call return?
Why. Every call gets its own total on the stack of the thread that made the call. Nothing is shared, so there is nothing to race on. A data race needs two threads touching the same memory; fifty calls create fifty different variables.

What is the main reason to run work in separate processes instead of threads?
Why. Separate address spaces are the whole point of a process. Threads run on many cores just as well, they are cheaper to create, and they share data more easily, which is exactly why they need synchronization.

An exception is thrown inside a thread and nothing catches it. What happens?
Why. An exception escaping a std::thread's function calls std::terminate, which ends the process. In Java the thread's uncaught exception handler prints the stack trace and that thread dies, while the JVM keeps running as long as other non-daemon threads remain. Either way, shared data the thread was updating may be left half changed.

Two processes on the same machine need to exchange data. Which statement is true?
Why. Each process has its own address space, so an address in one means nothing in the other. The OS offers several IPC mechanisms; a shared memory segment is the one case where both processes deliberately map the same physical pages, and then they need synchronization just like threads do.

Why. Both threads are in progress at once, so the program is concurrent. Only one can execute at any instant on one core, so nothing runs in parallel. A single core can hold any number of threads; the scheduler switches between them.
From: Concurrency versus parallelism
Two threads run count += 1 on a shared counter, on a machine with exactly one core. Can an increment be lost?
Why. Preemption can stop thread A after it has read the value into a register and before it writes it back. Thread B then does a full increment, and A writes its stale result over it. No second core is needed for that interleaving.
From: Concurrency versus parallelism
A job is 90 percent parallelizable. Using Amdahl's law, what is the best speedup on 8 cores?
Why. 1 / (0.1 + 0.9 / 8) = 1 / 0.2125, which is about 4.7. The tempting answer, 7.2, multiplies 8 by 0.9, but the serial 10 percent does not shrink at all, so it takes almost half of the remaining time. With unlimited cores the ceiling is 1 / 0.1 = 10.

Node.js serves 10,000 open connections from a single JavaScript thread. Which statement fits?
Why. Thousands of requests are in progress at once, so it is concurrent. The JavaScript runs on one thread, so the handlers never execute at the same instant. It works because most of each request's time is spent waiting, and the waits overlap.

Why. A single SIMD instruction is one line of work, so there is no concurrency, yet it performs 8 additions at the same instant in hardware. The event loop is concurrency without parallelism, turn taking is concurrency on one core, and the pool is both.

Why. A sleeping or waiting thread does not need the core, so all four waits overlap even on one core. The core is needed only for the tiny amount of computing before and after each wait. That is why concurrency helps I/O bound work regardless of the core count.

From: The scheduler, time slices and context switches
A thread calls a system call that returns immediately, such as getpid(). Is that a context switch?
Why. A system call is a mode switch: privilege changes, the thread does not. A context switch happens only when the kernel decides to run a different thread, for example because the call has to wait. Mixing the two up is a common interview slip.

Which part of a context switch's cost is usually larger?
Why. The registers, even with the vector state, come to only kilobytes and are saved in well under a microsecond. Refilling caches and the TLB after a switch can cost far more, depending on how much data the thread touches. Stacks are never copied; they stay where they are in memory.

Three jobs arrive at time 0 in the order A, B, C, with CPU bursts of 6, 3 and 1 ms. What is the average waiting time under shortest job first (no preemption)?
Why. SJF runs C [0, 1), B [1, 4), A [4, 10). Waiting times are C 0, B 1, A 4, so the average is 5 / 3, about 1.67 ms. The tempting 5 ms is wrong twice over: it is the FCFS average waiting time (A 0, B 6, C 9, the convoy effect of running the long job first), and it is also SJF's average turnaround time (1, 4 and 10), so it catches anyone who mixes up waiting and turnaround. 3.33 ms is the total 10 ms divided by three jobs, and 1 ms is only B's wait.
From: The scheduler, time slices and context switches
Round robin with a quantum of 2 ms. Job X (burst 5 ms) and job Y (burst 3 ms) both arrive at time 0, X first in the queue. Ignoring switch costs, what is the average turnaround time?
Why. The schedule is X [0, 2), Y [2, 4), X [4, 6), Y [6, 7), X [7, 8). Y completes at 7 and X at 8, so turnaround is 7 and 8, average 7.5 ms. Waiting times are 8 - 5 = 3 for X and 7 - 3 = 4 for Y. 6.5 ms is what you get if Y runs first, 5.5 ms is what shortest job first would give (Y at 3, X at 8), and 8 ms is only the time the last job finishes. Why. The standard describes yield as giving the implementation an opportunity to reschedule. If no other thread is waiting for that core, it returns at once. It is useful inside spin loops to be polite, never as a way to order threads.
From: The scheduler, time slices and context switches
1,000 threads are blocked on a condition variable, waiting for work that has not arrived. What do they cost?
Why. A blocked thread is off every run queue, so it uses no CPU until it is woken. That is the difference from spinning, which would cost a core per thread. But "no CPU" is not "nothing": memory for stacks and kernel structures stays allocated, and any locks or connections the threads hold stay held.
From: Thread states and what blocking really does
Thread W is waiting on a condition variable (or a Java monitor's wait()). Thread N notifies it while still holding the lock. What happens to W right away?
Why. Waiting releases the lock, and returning from the wait requires taking it back. While N holds it, W is woken but stuck (in Java its state is BLOCKED). When N releases the lock, W competes for it with any other thread, so by the time W runs, the condition it waited for may no longer hold: always re-check it in a loop.

In the five-state model, a thread is waiting for disk I/O and the I/O completes. Which state does it move to next?
Why. Waiting goes only to ready. Why. Pinned means the JVM cannot unmount the virtual thread, so the carrier sits blocked with it. In Java 21 this happens inside synchronized and native code, and the scheduler does not add carriers to compensate. With all carriers pinned, no other virtual thread can run.

A machine uses 32-bit virtual addresses and 4 KB pages. How many bits form the page offset, and how many pages can one address space hold?
Why. 4 KB is 2^12 bytes, so 12 bits address a byte within a page. The remaining 32 - 12 = 20 bits are the page number, giving 2^20 pages of 4 KB, which is the full 4 GB. The tempting slip is to give the page number the same 12 bits as the offset.
From: Virtual memory and paging
FIFO page replacement with 3 frames, all empty at the start. How many page faults does the reference string 1 2 3 1 4 1 2 cause?
Why. 1, 2, 3 fault (3). The second 1 hits. 4 faults and evicts 1, the oldest arrival (4). 1 faults and evicts 2 (5). 2 faults and evicts 3 (6). LRU would take only 5 faults here, because it keeps the recently used 1 when 4 arrives.
From: Virtual memory and paging
A program touches a page of freshly allocated anonymous memory for the first time. What happens?
Why. Allocation only reserved addresses. The first touch faults, and the kernel satisfies it from memory alone by handing over a zeroed frame, so it is minor. Major faults need storage: a swapped out page, or a file page missing from the page cache.
From: Virtual memory and paging
Which statement about Belady's anomaly is true?
Why. On 1 2 3 4 1 2 5 1 2 3 4 5, FIFO takes 9 faults with 3 frames and 10 with 4. LRU and OPT are stack algorithms: their resident set with more frames always contains the set with fewer, so more frames can never cause more faults.
From: Virtual memory and paging
A process with a 2 GB heap calls fork. The child changes one variable on one page and then exits. Roughly how much memory was copied for the heap?
Why. fork copies the page tables and shares every frame read-only. The child's single write faults, and the kernel copies just that page (a whole 2 MB page if transparent huge pages back the heap). The page tables themselves are copied, though, so forking a process with a huge address space is not free. "2 GB" is the tempting answer if you picture fork as a memory copy.
From: Virtual memory and paging
Thread A unmaps a region of memory while threads B and C of the same process are running on other cores. What does the kernel have to do?
Why. All threads share one set of page tables, but each core keeps its own TLB. Cores that may hold the old translations get an inter-processor interrupt to flush them, otherwise B or C could still reach memory that no longer belongs to the process. The more cores run the process, the more each shootdown costs.

Why. A put changes the page cache through the mapping; the kernel writes dirty pages back on its own schedule. force() asks for the mapped content to be written to the device and returns after it is, which is the durability point you need for a log or an index.
