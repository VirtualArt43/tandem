Why. A lock prevents two prints from overlapping, but the foo thread can release it and take it straight back before bar is scheduled. From: Readers and writers, three ways
In the lightswitch, why is the room lock a semaphore rather than a ReentrantLock or std::mutex?
Why. A mutex has an owner and must be released by that owner: Java throws IllegalMonitorStateException and C++ has undefined behavior otherwise. A semaphore allows a different thread to release a permit, which is what the lightswitch needs. Neither primitive is inherently faster or fair, and holding one mutex while acquiring another is permitted when the lock ordering is safe.

Which clock should measure elapsed time for refilling a token bucket?
Why. Wall clock time can be corrected backwards or forwards at any moment, which corrupts elapsed time. Elapsed-time sources avoid wall-clock corrections. Clock values may repeat at the available resolution, and Java nanoTime values may wrap, so use bounded differences. Choosing milliseconds does not make wall time monotonic. A fixed window counter allows 100 requests per minute, with windows starting on the minute. What is the most a client can get through in about two seconds?
Why. 100 at 12:00:59 fill the old window, and 100 at 12:01:00 fill the new one. A two-second interval can overlap at most two minute windows, so 200 is achievable and cannot be exceeded. Neither 100 nor 101 is the maximum, and each window's finite quota rules out unlimited admissions. An exact sliding log removes this boundary burst; a weighted sliding counter only approximates a rolling limit.
