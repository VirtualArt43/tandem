Elevator controller

Thread-safe designsmedium55 minAppleMicrosoft

Call assignment, door state and movement must agree even when passengers press buttons together. Use a simulated clock to make every physical step observable.

The task

Implement E cars in an F-floor building, with exactly one controller thread per car. Cars are numbered from zero to E - 1 and start at floor zero with closed doors. Hall calls include floor and direction; car calls target a specified car. Public operations must be thread-safe.

Rules

  • E is positive, F is at least two, IDs are nonnegative signed 64-bit integers and floors are in [0, F). Hall direction is up 1 or down -1; reject outward calls at terminal floors. Direction describes the passenger request but this baseline does not coalesce calls or optimize travel direction.
  • Validate every argument before checking shutdown or duplicate IDs. Invalid arguments throw IllegalArgumentException in Java or std::invalid_argument in C++, without changing any state. A valid call after shutdown begins throws IllegalStateException or std::logic_error, including a repeated ID.
  • IDs share one lifetime-wide deduplication namespace. The first accepted ID returns true and is queued exactly once; valid repeats return false, including after service or through the other call method. Only the first accepted request determines its destination. Different IDs for the same floor remain separate requests.
  • Assign accepted hall calls round robin, starting with car zero. Only a newly accepted hall call advances the assignment counter. Car calls, duplicates and invalid calls leave it unchanged. Deduplication, car selection and enqueue form one atomic admission; concurrent calls may be admitted in either order.
  • Each car serves its queue in admission order. New arrivals append and never overtake queued requests. If a request has q requests ahead at admission, it is served within (q + 1) * (F + 1) + 1 subsequent ticks granted to that car, assuming the controller is scheduled, callbacks return and shutdown does not cancel it.
  • Each clock grant permits one step. If doors were open at its start, only close them. Otherwise move one floor toward the queue head, or, if already at its floor, open doors and serve that request. Do not move and operate doors in the same tick. With closed doors and no pending request, stay at the same floor.
  • The supplied clock blocks controllers until a grant, even when a car has pending work. It can grant ticks independently to different cars. stop() wakes every waiter and makes future waits return false. Use the supplied clock rather than sleeping to simulate movement.
  • The supplied thread-safe, nonthrowing, nonreentrant observer receives exactly one snapshot per granted step, including idle steps, on that car's controller thread. Call it outside all controller locks so a slow observer does not block admission or another car. step starts at one and increases by one for every event from that car; served is -1 except on an open-and-serve step.
  • Shutdown closes admission, removes and returns unserved IDs in any order, stops the clock and joins all controllers. Every accepted ID must be either served once or returned once, never both. Already dequeued service callbacks finish before return. Concurrent shutdown callers all wait for controllers to finish; only the first returns pending IDs and subsequent calls return an empty list. Do not call shutdown from a controller callback.

The clock and observer remain alive until shutdown completes. They do not throw during this exercise; in Java, tests do not interrupt controller threads. Queues have no capacity limit here. In C++, destruction must also stop and join owned threads if shutdown has not already done so.

Worked example

From floor zero, a car queued for floor two moves to one, moves to two, opens and serves, then closes on four separate ticks. A queued request for another floor can start moving only on a later tick.

What the tests check

  • Invalid building sizes, IDs, floors, car indices, directions and terminal-floor calls throw the specified exception without consuming an ID or a round-robin turn. Zero and the largest signed 64-bit ID are valid; buildings with two, six and seven floors are exercised.
  • A fixed event trace grants individual cars ticks and checks exact floor, door state, service ID and step number. It covers upward and downward motion, same-floor requests, idle ticks, explicit car targets and round robin unaffected by car calls or duplicates.
  • Repeated IDs are ignored before and after service, including across the two admission methods. Eight callers also race on the same 16 IDs; each ID is accepted and served exactly once.
  • FIFO heads reach service on ticks 6, 13 and 15 while new requests keep arriving behind them. A separate seeded contention test checks all 73 accepted requests, correct destinations and finite completion.
  • Three callbacks are held open together. Calls targeting those cars must still finish. Two shutdown callers must wait for those callbacks, reject both kinds of new admission and return pending IDs exactly once.
  • Three rounds race hall calls, car calls, clock grants and shutdown. The accepted IDs must equal the disjoint union of served and cancelled IDs. Idle shutdown must wake blocked controllers and repeated shutdown must return no IDs.
  • Timed joins and a whole-suite watchdog bound failures. C++ runs under ThreadSanitizer to detect data races.

Clock handshakes order the exact trace tests. The shutdown check uses a short observation window while callbacks are held by explicit gates. Seeded inputs are repeatable, but the operating system chooses concurrent interleavings; these tests exercise the contract without proving every possible schedule.

What the interviewer asks after your first version works. Try to answer each one out loud before you open it.

What were the reported concurrency follow-ups?
Apple asked which elevator components require synchronization. Microsoft asked about a blocking queue in the multithreaded version, fairness and idempotency. This exercise drills atomic admission, FIFO fairness and idempotency; the supplied clock provides blocking, so a library blocking queue is not required.
Would nearest-car assignment be better?
It can reduce travel but needs a coherent assignment decision and a starvation policy. A stream of nearby calls can delay a distant one without age-based priority or bounded overtaking.
How do you batch hall calls by direction?
Use directional stops or a LOOK/SCAN policy and track every request identity at a stop. Define which opposite-direction calls wait for the return trip and prove a waiting bound under continuing arrivals.
How do sensor faults change the design?
Use a separate safety state machine with explicit door-closed confirmation, motion authorization and emergency stop. This simulated controller is an interview model, not real elevator safety software.
Why return unserved IDs on shutdown?
It makes the boundary observable: every accepted request is either served once or cancelled once. Silently abandoning queued calls would make the exactly-once accounting impossible to test.

Try for at least twenty minutes first. Reading a solution feels like learning; writing one is learning.

Key idea and invariants

A dispatch critical section deduplicates and assigns each call to one queue. Each car thread is the sole executor of its physical steps; enqueue and shutdown use that car's mutex to modify the queue. The step rule never combines movement with door operation, and FIFO prevents new calls from overtaking old ones.

Why these primitives

A short dispatch mutex protects identity and round-robin assignment. Per-car locks protect queues and snapshots, while the supplied blocking clock drives deterministic time. Observers execute after unlocking, so cars can report concurrently and admission can continue while a callback is slow. Shutdown releases dispatch and car locks before joining, and clock stop wakes every blocked controller. A separate shutdown mutex serializes closers so a repeated call cannot return before the first caller finishes joining.

Pitfalls and broken interleaving

The broken code closes doors, then independently checks whether a queued movement is possible in the same tick. Its final snapshot may show closed doors, but it violated the required tick-level interlock. The harness compares consecutive states rather than checking only the final boolean.

Cost and interview explanation

Queue operations take amortized O(1) time. For R lifetime IDs, Java hash-set deduplication takes expected O(1) and the C++ ordered set takes O(log R). Storage is O(E + R + Q) for E cars, remembered IDs and Q pending requests; deduplication memory grows even after requests are served. A request has at most F - 1 travel ticks plus open and close, giving the FIFO bound, with one extra tick for doors already open at admission. Shutdown scans pending queues and waits for in-flight callbacks and controller exit. Say: “I will prove ownership of each request and a tick-level door interlock first. Round robin and FIFO give a clear fairness baseline before optimizing route length.”
