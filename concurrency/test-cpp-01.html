Thread A runs data = 42; ready = true; and thread B runs while (!ready) {} std::cout << data;. Both variables are plain globals (bool ready, int data), there is no other synchronization, and the program is built with -O2. What can happen?
Why. Both variables are raced on, so the program has no defined meaning. Concretely, the compiler may load ready once and spin forever, and the writes or reads may be reordered so B prints 0. "Always terminates" assumes undefined behavior is somehow bounded; it is not. The source order of A's writes guarantees nothing to B without a happens-before edge.

log.h contains static std::mutex log_mutex;. Both a.cpp and b.cpp include it, and both lock log_mutex before appending to one global std::string log_buffer defined in log.cpp. What is true?
Why. static at namespace scope gives internal linkage: each translation unit gets its own private log_mutex, so there is no link error and no mutual exclusion. Use inline std::mutex (C++17), or extern in the header with one definition in a .cpp, or hide the mutex inside log.cpp behind a function.

A header defines void log_line(const std::string& s) { /* body */ }, not inline and not a template. Two .cpp files include it. In a normal Clang build, what diagnostic would you expect?
Why. Each translation unit contains an external definition of log_line, which breaks the one definition rule, and a normal linker reports duplicate symbols. The C++ standard does not require a diagnostic for every cross-translation-unit ODR violation. Marking the function inline makes identical definitions legal, and then the linker does keep one. "Each file calls its own copy" is what static would do.

Two threads write, without any lock, to different members of one object: struct S { char a; char b; } s; Thread 1 writes s.a and thread 2 writes s.b. Is this a data race?
Why. Since C++11 every scalar object is its own memory location, and the compiler must not invent writes to neighbouring locations. Sharing a cache line can cost performance (false sharing) but not correctness. The exception is adjacent bit-fields, which form one memory location.
