What does it print with lock.wait(500) as written, and what if that line becomes Thread.sleep(500)? Assume no spurious wakeup.
Why. lock.wait(500) releases the monitor and reacquires it before returning. That permits main to print M while the worker waits, producing M T, but does not guarantee main runs within 500 ms. If the wait times out and the worker reacquires the monitor first, it prints T M. The latch proves only that the worker entered the synchronized block, not that main acquires the monitor before the timeout. Both orders were reproduced, with the second probe delaying main. Thread.sleep(500) keeps the monitor throughout, so main cannot enter until after the worker prints T: that version prints T M. A timeout creates an opportunity for another thread to run, not a scheduling promise.

Why. A semaphore counts permits without tracking owners. Here the count goes from 2 to 1, then three releases raise it to 4. acquire(3) leaves 1. tryAcquire(2) requires both requested permits, so it returns false and leaves that one permit untouched: 4 false 1. The initial count is not a ceiling, but the count is not mathematically unbounded: Java stores it as an int, and overflowing Integer.MAX_VALUE on release throws Error. A negative initial count is also legal; starting at -1 requires two releases before a single permit can be acquired. Extra releases can therefore silently raise an application's intended concurrency limit long before any overflow.

Why. Both w1 prints precede the first [round 1], because each worker prints before counting down and the first await() waits for both. A CountDownLatch stays at zero once released, so the second await() does not wait for the second round. Usually [round 2] prints before either w2, as in the ordinary run. But the scheduler can delay main until one or both workers finish their sleeps, so [round 2] may also fall between or after the w2 prints. A delayed-main probe produced w1 w1 [round 1] w2 w2 [round 2]. Extra decrements at zero do nothing, and these non daemon workers still finish.
