Reorder buffer

Thread-safe structureshard55 minGoogleBloomberg

Workers finish out of order. Your consumer still needs the next sequence, and a missing item must not let buffered memory grow without a bound.

The task

Complete the bounded ReorderBuffer, starting at sequence zero. put accepts out-of-order items; take returns exactly the next number, blocking until its item or an explicit gap is ready. Use the supplied clock for the optional missing-item policy, implemented in this exercise through tick().

Rules

  • A positive window W stores only sequences in [next, next + W). A put W or more ahead blocks until the window moves. Numbers already consumed, skipped or buffered return false. Java null payloads are invalid; C++ payload moves do not throw. Sequence values are nonnegative and at most the signed maximum minus W + 1.
  • When next is missing but a later item is stored, start a hole timer. At elapsed time at least gapTimeoutMs, tick commits gaps up to the first stored item and wakes takers. No later buffered item means no gap, regardless of elapsed time. A new hole gets a new timer. Timeout zero is allowed.
  • The injected clock is monotonic, nonnegative, nonthrowing and nonreentrant. The caller advances it and calls tick; there is no background timer. Without ticks, no gaps are emitted.
  • All methods are thread safe. Java waiting is interruptible and does not insert or consume on interruption. buffered() counts items, not gaps, and never exceeds W. No shutdown or strict FIFO admission policy is promised.
  • A blocking producer must not withhold the missing low sequence behind arbitrarily far-ahead work on the same thread. The stress test shuffles local blocks across eight producers so the next required submission can reach the buffer.

Worked example

With W = 4, store sequences 2 and 1. A take waits for 0. If 0 arrives, output is 0, 1, 2. If its hole times out first, output is gap 0, item 1, item 2; a later put of 0 is rejected.

What the tests check

  • Ordered output and duplicate rejection, both sequentially and with eight producers on seeded shuffled input.
  • Eight far-ahead submissions overlap while blocked; each wakes as its own sequence becomes eligible and the memory bound holds.
  • Explicit-clock checks cover just before and at each hole deadline, several skipped numbers, fresh timers, idle periods and late arrivals.
  • Bounded joins and a watchdog turn missed notifications into a failure line.

What the interviewer asks after your first version works. Try to answer each one out loud before you open it.

What were the reported follow-ups?
Bloomberg asked ordered-stream concurrency, locks and missing IDs in 2026. Google reports include timestamp-ordered video frames in 2024 and several topics with a watermark in 2022.
How does a watermark differ from this timeout?
A watermark expresses progress knowledge across input streams, often their minimum safe timestamp. A local timeout is a policy decision to give up and can discard an item that arrives later.
Why can notifying one producer deadlock?
Each producer waits for its own sequence. A notification can wake a still-ineligible far-ahead producer while the eligible one remains asleep and the consumer cannot advance.
Can all producer input be shuffled arbitrarily?
Not with a bounded blocking API and a fixed small worker set: all workers can block on high numbers while low numbers remain unsubmitted. Use an admissible schedule, nonblocking rejection or a dispatcher that can still deliver the next item.
How would you add close?
Specify whether to drain contiguous items, emit final gaps or abort. Include closed in both wait predicates and wake every producer and consumer so no operation waits for an impossible future.

Try for at least twenty minutes first. Reading a solution feels like learning; writing one is learning.

Key idea and invariant

The original ring-buffer design stores at most one item for every slot in the moving window. A mutex protects next, item presence, count, the timer and the committed gap boundary together. The first stored item after a hole bounds the scan used by tick.

Why these primitives

Separate condition variables describe next-item readiness and window movement. Predicate loops tolerate spurious wakes. Producers need a broadcast because their sequence predicates differ; takers can hand off notification as next advances. Clock injection makes the timeout a state transition, not a sleep-based guess.

Pitfalls and broken schedule

The preserved Java broken version wakes one producer after freeing a slot. If 11, 10, 9 and 8 are woken while only 4 through 7 become eligible, each returns to sleep. The consumer then waits for 4, whose producer never received a notification. The C++ broken version instead commits gaps in tick but never wakes the blocked taker. Its deadline test catches that missed notification. State can be correct while progress is broken.

Cost and interview explanation

Normal put and take use constant-time ring operations and O(W) storage. Tick can scan O(W) slots. Say: “I will separate item readiness from window admission. A timeout commits gaps under the lock, and advancing the window broadcasts because each producer is waiting for a different number.”
