Why. With no happens-before edge between the flag write and read, the memory model permits the worker to keep observing the old value. Hoisting the read is one possible optimization. A service starts a new platform thread for every request. Under a traffic spike it crashes with OutOfMemoryError: unable to create native thread, while heap usage is only at 40 percent. What ran out?
Why. Thread stacks are native memory reserved per thread (typically 1 to 2 MB each), and the operating system also limits how many threads a process may have. Neither is part of -Xmx, so the heap can look healthy. Classes and compiled code are shared by all threads. The fix is a bounded pool or virtual threads, not a bigger heap.

A plain (non-volatile) long field is written by one thread and read by another with no synchronization. What does the Java Language Specification allow the reader to see?
Why. The specification lets a non-volatile long or double write be treated as two 32-bit writes, so a racy read can be torn. 64-bit JVMs do not split them in practice, but the language allows it. Reads and writes of references, of every other primitive type, and of any volatile field are always atomic.
