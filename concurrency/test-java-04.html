Why. Dispatch is active during Java construction. The override reads the default field value before the initializer runs. Final prevents another subclass from replacing the override; it does not change construction order.

An initially empty inbox is intended to hold at most one message. Its size() and add() use the same lock, but add() inserts without checking capacity. Two callers each execute if (size() == 0) add(message). What is possible?
Why. Both checks can observe zero before either insertion, so the size can become two. The common lock prevents data races on the deque, but not this race between complete method calls.
