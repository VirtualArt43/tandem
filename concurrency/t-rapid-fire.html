Rapid fire

Over fifty short questions for the last week before interviews, each with the one to three sentence answer you should say without thinking.

1CorethreadsprocessesLinkedIn
Process or thread, in one sentence each.
Model answer

A process owns an address space and resources such as open files; a thread is a flow of execution inside a process that shares those resources but has its own stack and registers.

2Coreraces
Data race versus race condition?
Model answer

A data race is two unsynchronized accesses to the same location from different threads, at least one a write and at least one not atomic (undefined behavior in C++). A race condition is any bug where the result depends on timing; it can exist with no data race, as in check-then-act over two individually locked calls.

3CoreracesatomicityGoogle
Why is count++ not thread-safe?
Model answer

It is three steps (read, add, write), so two threads can read the same value and one increment is lost. Fix it with an atomic increment, a lock, or per-thread counts merged at the end.

4Corevolatilejava
Does volatile make count++ safe in Java?
Model answer

No. It gives visibility and ordering for individual reads and writes, not atomicity for a read-modify-write; use AtomicInteger or a lock.

5CorevolatilecppNvidia
Is C++ volatile useful for sharing data between threads?
Model answer

No. It gives no atomicity and no ordering between threads, and a race on a volatile object is still undefined behavior; use std::atomic.

6CoredeadlockNvidia
The four conditions for deadlock?
Model answer

Mutual exclusion, hold and wait, no preemption, and circular wait. All four are needed, so break one, usually circular wait with a global lock order.

7Corelivelock
Livelock in one line?
Model answer

Threads keep reacting to each other and changing state, but none makes progress, like two people stepping aside the same way in a corridor; fix it with randomized backoff or a fixed order.

8CorestarvationRubrik
What is starvation, and the usual fixes?
Model answer

The system progresses but one thread never gets its turn, for example a writer behind endless readers. Fix it with fairness: FIFO admission, aging, writer preference, or a cap on consecutive turns for one group.

9Corecondition-variable
Why must a condition wait sit in a while loop?
Model answer

Wakeups can be spurious, and another thread can consume the condition between the notify and your reacquiring the lock, so you must recheck the predicate every time you wake.

10CorenotifyLinkedIn
notify or notifyAll?
Model answer

notifyAll unless every waiter waits for the same predicate and any single one can proceed. Better still, use separate Condition objects per predicate and signal exactly the right one.

11Corelost-wakeup
What is a lost wakeup?
Model answer

A notification sent before the waiter starts waiting, so the waiter sleeps although its condition is already true. Prevent it by changing the state under the same lock the waiter holds while it checks the predicate.

12CoresemaphoremutexLinkedInNvidia
Mutex versus binary semaphore?
Model answer

A mutex has an owner, and only the owner may unlock it; a semaphore has no owner, so any thread may release it. Use a mutex for mutual exclusion, a semaphore for counting and signaling.

13CorespinlockNvidia
When should a lock spin instead of sleep?
Model answer

When the expected wait is shorter than two context switches and the holder is running on another core. Never on a single core, and never with long critical sections.

14Corereentrancy
What is a reentrant lock?
Model answer

One the owning thread can acquire again without deadlocking itself; a hold count tracks the nesting. Java's synchronized and ReentrantLock are reentrant; std::mutex is not.

15Coreexecutorsjava
execute versus submit on an ExecutorService?
Model answer

execute runs a task and sends any exception to the thread's uncaught exception handler. submit returns a Future that captures the result or exception, which nobody sees unless someone calls get.

16CoreshutdownexecutorsRubrik
shutdown versus shutdownNow?
Model answer

shutdown refuses new tasks but runs every queued one. shutdownNow refuses new tasks, removes and returns the queued ones, and interrupts the running ones, best effort.

17CoreinterruptionjavaRubrik
You catch InterruptedException. What do you do?
Model answer

Propagate it, or restore the flag with Thread.currentThread().interrupt() and stop what you were doing. Never swallow it.

18CoreconcurrenthashmapjavaDatabricks
Why is ConcurrentHashMap safe when HashMap is not?
Model answer

ConcurrentHashMap reads without locks through volatile fields, CASes new nodes into empty bins, locks only the affected bin on other writes, and resizes cooperatively. HashMap does unsynchronized read-modify-writes that lose entries and can corrupt its structure.

19CoreconcurrenthashmapjavaDatabricks
Why does ConcurrentHashMap reject null keys and values?
Model answer

So that get returning null can only mean "absent". Otherwise you would need a separate containsKey, and that pair of calls is itself a race.

20CorecasatomicsDatabricksRubrik
What is compare-and-swap?
Model answer

An atomic instruction that writes a new value only if the current value equals the expected one, and reports whether it did. It is the building block of lock-free algorithms and of most lock implementations.

21Seniorabalock-freeRubrik
What is the ABA problem?
Model answer

Between your read and your CAS, the value changes from A to B and back to A, so the CAS wrongly succeeds; in a lock-free stack this can link a freed node. Fix it with a version stamp next to the pointer, hazard pointers or epochs, or rely on a garbage collector.

22Corelongadderjava
LongAdder or AtomicLong?
Model answer

LongAdder for hot counters that are written far more than read, because it spreads increments across cells. AtomicLong when you need the exact current value or compare-and-set logic.

23Corehappens-before
Happens-before, in one sentence?
Model answer

If A happens-before B, then A's writes are visible to B. You create the edge with locks, volatile or atomic accesses, thread start and join, and the concurrent utilities.

24Seniormemory-ordercpp
Acquire and release, in one sentence?
Model answer

A release store publishes every write made before it to any thread whose acquire load reads that stored value.

25Seniorseq-cstmemory-order
When do acquire and release fall short, so you need seq_cst?
Model answer

When each thread writes one variable and then reads another (store buffering, Dekker's algorithm). With acquire and release, both threads may read the old values.

26Corefalse-sharing
What is false sharing?
Model answer

Threads writing different variables that share one cache line, so the line ping-pongs between cores. Fix it with padding or alignment to separate lines, or with per-thread data merged at the end.

27Corecache-line
How big is a cache line?
Model answer

Typically 64 bytes on x86; macOS reports 128 bytes on Apple M-series chips. Coherence, and therefore false sharing, works on whole lines, so pad hot per-thread fields to the line size of the machine you run on.

28Coremesicache-coherenceMicrosoft
The MESI states?
Model answer

Modified, Exclusive, Shared and Invalid. To write, a core must hold the line exclusively, which invalidates every other copy.

29Corecontext-switchNvidia
What does a context switch cost?
Model answer

On the order of microseconds directly, plus cold caches and TLB afterwards, which often cost more. Switching between processes also changes the address space.

30Corefutex
What is a futex?
Model answer

A Linux primitive that keeps the lock state in user memory and enters the kernel only to sleep or wake. FUTEX_WAIT sleeps only if the value is still what the caller expected, which prevents lost wakeups.

31Seniorpriority-inversion
How do you fix priority inversion?
Model answer

Priority inheritance (the lock holder temporarily runs at the highest waiter's priority) or a priority ceiling (the holder runs at the highest priority of any task that uses that lock).

32Corelittles-law
State Little's law and use it once.
Model answer

In-flight work equals arrival rate times time in the system: 1,000 requests per second at 0.2 seconds each means about 200 in flight.

33Seniorqueueing
In an M/M/1 queue at 90 percent utilization, how long does a request spend in the system?
Model answer

About 10 times the service time, S / (1 minus ρ); the waiting part alone is about 9 times. Latency explodes near 100 percent.

34Corepool-sizingDatabricks
Pool size for CPU-bound versus I/O-bound work?
Model answer

CPU bound: about the number of cores. I/O bound: cores × (1 + wait time / compute time), capped by downstream limits such as database connections and per-host politeness.

35CorebackpressureDatabricks
What is back-pressure?
Model answer

Letting a slow consumer's limit propagate upstream, with a bounded queue that blocks or rejects, instead of letting memory grow without limit.

36CorefsyncdurabilityDatabricks
write versus fsync?
Model answer

write puts the data in the kernel's page cache, which survives a process crash but not a kernel crash or a power cut. fsync forces it to stable storage, which survives all three (if the device honors cache flushes).

37Coregroup-commitDatabricks
What is group commit?
Model answer

One fsync covers a whole batch of writes that queued up while the previous fsync ran, so throughput grows with load while latency stays at roughly one or two fsyncs.

38CoreidempotencyStripeRippling
What is an idempotency key?
Model answer

A client-generated id for one logical operation. The server stores the result under a unique constraint and returns that stored result for any retry with the same key, instead of applying the operation twice.

39Seniorfencing-tokendistributed-lock
What is a fencing token?
Model answer

A number that increases with every lock grant. The protected resource rejects writes that carry a lower number than one it has already seen, which stops a paused former lock holder.

40Coreisolationwrite-skew
Which anomaly does snapshot isolation still allow?
Model answer

Write skew: two transactions read overlapping data, check a condition, and write different rows, together breaking an invariant that each one preserved alone.

41CoreoptimisticpessimisticMeta
Optimistic versus pessimistic locking, one line each?
Model answer

Pessimistic: lock first, and others wait. Optimistic: proceed without locking, check a version when writing, and retry on conflict; it wins when conflicts are rare.

42Corestd-threadcpp
What happens when a joinable std::thread is destroyed?
Model answer

std::terminate is called. Join or detach it first, or use std::jthread, which requests stop and joins in its destructor.

43Seniorstd-asynccpp
How can std::async end up synchronous?
Model answer

The default policy may defer the task until get, and the future returned by std::async blocks in its destructor. Ignore the returned future and the call waits at the end of the statement.

44Corecondition-variablecpp
Which lock does std::condition_variable require?
Model answer

A std::unique_lock<std::mutex> on the mutex that guards the predicate. For any other lock type, use std::condition_variable_any.

45Seniorshared-ptrcpp
Is std::shared_ptr thread-safe?
Model answer

Its reference count is. One shared_ptr variable read and written concurrently is a data race, and the pointee is not protected at all; use std::atomic<std::shared_ptr<T>> (C++20) to share the variable itself.

46Corevirtual-threadsjava
What do virtual threads help with, and what don't they help with?
Model answer

They make blocking, I/O-bound code scale to huge concurrency. They do nothing for CPU-bound work, should never be pooled, and in JDK 21 to 23 they pin their carrier when they block inside synchronized.

47SeniorcompletablefuturejavaGoogle
Which thread runs a thenApply callback?
Model answer

The thread that completes the future, or the registering thread itself if the future was already complete. The Async variants run on the given executor, or the common pool by default.

48Corethreadlocaljava
What goes wrong with ThreadLocal in a thread pool?
Model answer

Values survive into the next task on the same thread, leaking memory and, worse, context such as a user identity. Always remove() in a finally block.

49CoretestingDatabricks
Can tests prove that code has no races?
Model answer

No. Tests sample a few interleavings on one machine. Correctness comes from reasoning (every shared access ordered by happens-before), with ThreadSanitizer, stress tests and jcstress as evidence.

50Corethreadsanitizer
What does ThreadSanitizer catch, and what does it miss?
Model answer

It catches data races on the paths a run executes, even when the output happened to be right. It misses logic races that involve no data race, and code that never ran. On Linux it also reports lock order inversions (potential deadlocks); Apple clang's build does not.

51CorecrawlerterminationRubrikDatabricks
How does a multithreaded crawler know it has finished?
Model answer

A counter of accepted but unfinished pages reaches zero; it is incremented before a URL is queued and decremented after its links were added. An empty queue alone is not enough, because a busy worker may be about to add more.

52Coreread-write-lockRubrik
When does a read-write lock not help?
Model answer

When "reads" actually mutate (an LRU get moves the entry), when critical sections are tiny so the extra bookkeeping dominates, or when writes are frequent.

53Seniordouble-checked-locking
Why does double-checked locking need volatile in Java?
Model answer

Without it, the reference can become visible before the constructor's writes, so a second thread can use a half-built object.

54Coreforkprocesses
What is special about calling fork in a multithreaded program?
Model answer

Only the calling thread exists in the child, and any lock another thread held stays locked forever there, so the child should call only async-signal-safe functions until it calls exec.

55CoreschedulingRubrik
Round robin with a quantum that is too small, or too large?
Model answer

Too small and context-switch overhead dominates; too large and it degenerates into first come, first served, with poor response times.

56Seniorbuddy-allocatorRubrik
In a buddy allocator, how do you find a block's buddy?
Model answer

XOR the block's offset (from the start of the region) with its size, 2^k. If that buddy is free and of the same order, merge the two and repeat one order up.

57Corecheck-then-act
Name the bug: if (!map.containsKey(k)) map.put(k, v) on a ConcurrentHashMap.
Model answer

Check-then-act: each call is atomic, but another thread can insert between them. Use putIfAbsent or computeIfAbsent.

58CorelatchbarrierRubrik
Latch versus barrier?
Model answer

A latch is one-shot: some threads count down and others wait. A barrier is reusable: a fixed group of threads wait for each other at the end of every phase.

59Corelock-orderingcpp
How do you lock two mutexes safely in C++?
Model answer

std::scoped_lock lk(a, b); in C++17, which has deadlock avoidance built in, or std::lock(a, b) followed by std::adopt_lock guards in C++11.
