Replica diff

Concurrent systemssenior70 minRubrik

When local computation is cheap and the network is expensive, compare compact evidence first and transfer only the partitions that disagree.

The task

Implement ReplicaDiff for two region-local maps. For each key, the higher version wins; on equal versions the US value wins. A key present in only one region is copied. Partition by key % buckets, compute bucket digests in parallel, exchange digests and transfer records only for differing buckets. Both maps must contain the same resolved union on success.

Rules

  • Keys and versions are nonnegative signed 64-bit integers. Values are ASCII byte strings. Counts and lengths fit unsigned 32-bit fields. Inputs are stable and exclusively owned during reconciliation. There are no deletes or tombstones in this version.
  • A record message is a big-endian four-byte record count followed by sorted records: eight-byte key, eight-byte version, four-byte data length and the data bytes. A digest is sixteen bytes over that same canonical encoding. Every message adds ten framing bytes. The supplied thread-safe channel copies its payload unchanged and counts actual bytes; from is zero for US and one for EU.
  • Send each EU digest to US. For a mismatch, send that EU bucket to US, resolve it locally, then send the merged bucket to EU. Do not inspect remote records directly to skip channel accounting. Matched buckets send no record payload.
  • Use up to workers threads, at least two for enough buckets. The nonthrowing probe wraps each worker once. Join all workers before returning. On a channel exception, propagate it after joining and leave both caller maps unchanged.
  • For the finite test corpus, assume the supplied-style sixteen-byte fingerprint has no collisions. The reference uses two explicitly noncryptographic 64-bit accumulators for portable practice; this is not an adversarial equality proof. Production collision handling is a required follow-up.
  • Test snapshots fit memory and thread creation succeeds. A real 32 GB deployment needs bounded streaming or external bucket files rather than copying both complete maps.

Worked example

US has key 7 at version 4 with data A; EU has version 4 with data B. The bucket must differ even though versions match, and the resolved data is A. At version 5, EU's value would win.

What the tests check

  • Higher-version winners, US tie preference, one-sided keys and exactly equal final maps.
  • Matching maps transmit one framed digest per bucket and no records.
  • At 82 differing records out of 8192, total counted bytes, including framing and digests, are less than ten percent of one full encoded map copy.
  • Four hashing workers overlap, measured by a counter; eight seeded independent sessions stress merging. Channel failure joins workers and leaves inputs unchanged.

Taught in: Parallel copies, chunked reads and caches over slow storage

What the interviewer asks after your first version works. Try to answer each one out loud before you open it.

What did the Rubrik report say?
The 2026 report describes roughly 32 GB maps in US and EU, at most five percent divergence, costly networking and cheap local compute, with exactly this version and US tie rule. Multiprocessing was out of scope in the reported first phase; this bank exercise adds parallel hashing as practice.
What if two different buckets have the same digest?
A digest can collide. Use a cryptographic digest with a documented risk model, or add verification when exact equality must be proved. The compact test fingerprint is not safe against adversarially chosen values.
Why not one digest for the whole map?
It detects disagreement but does not locate it. More buckets reduce mismatch payload but increase digest overhead. A Merkle tree refines only mismatching branches when the maps are very large or differences are clustered.
How do deletes and concurrent writes change the protocol?
Represent deletes with versioned tombstones and define snapshot epochs. Reconcile stable snapshots, then apply changes conditionally by version or retry; otherwise a digest and its later payload can describe different states.
How do you fit the reported data size?
Hash partitions locally using bounded buffers or external bucket files, exchange digest manifests, then stream differing buckets. Checkpoint batches and retry idempotently rather than holding two full copied maps in one process.

Key idea and invariants

The same key always belongs to the same bucket in both regions. A canonical digest covers the complete sorted record encoding. Matched buckets need only the digest exchange under the stated collision assumption. For every differing bucket, the union chooses a deterministic winner per key and sends the resolved bucket back.

Why these primitives

Workers own separate bucket slots, so map mutation is local until join. The channel is the only path for cross-region payloads and independently counts bytes. Failure slots are private to workers and read after join. C++20 joining threads provide cleanup; C++17 can use ordinary threads with a joining scope guard. Parent-thread commit keeps a failed exchange from partially replacing the caller maps.

Pitfalls and broken interleaving

The broken digest omits data and hashes only keys and versions. Equal-version conflicting records look identical, so the protocol never reaches the US tie-break rule. Hash-map iteration order, uncounted manifests, and one oversized bucket can also defeat the protocol or its bandwidth target.

Cost and interview explanation

Local work scans all bytes and sorts bucket records. Network cost is one digest per bucket plus the differing EU and resolved buckets, not just the changed records. Say: “I will define a stable serialization and count every wire byte. Bucket granularity controls the tradeoff between digest overhead and retransmitting unchanged neighbors.”
