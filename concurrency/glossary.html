Concurrency

Glossary

532 terms, each with what it looks like in Java and in C++.

A

ABA problemABA

A compare-and-swap succeeds because the variable holds the value you read, even though it changed to something else and back in between. With pointers to reused nodes, the swap can corrupt a lock-free structure.

Java rare for references because the garbage collector never reuses an object someone still points to; for reused nodes or plain values use AtomicStampedReference or a version numberC++ real whenever popped nodes are freed and their addresses reused; prevented by safe memory reclamation or a version tag next to the pointer
See also: Compare-and-swap, Treiber stack, Safe memory reclamation

AbstractQueuedSynchronizerAQS

The framework under most java.util.concurrent synchronizers: one int state changed by CAS, plus a FIFO queue of parked threads. Each synchronizer only decides what the state means.

Java ReentrantLock (state is the hold count), Semaphore (permits), CountDownLatch (the count), ReentrantReadWriteLock (read and write counts packed into one int)C++ no equivalent; build from std::atomic plus std::atomic::wait, or a mutex and condition variable
See also: Parking, Compare-and-swap, Reentrant lock

Access order

A LinkedHashMap mode in which every get or put moves the entry to the end, so iteration runs from least to most recently used. In this mode even a get changes the structure.

Java new LinkedHashMap<>(16, 0.75f, true)C++ done by hand by splicing a std::list node to the back on every access
See also: LRU cache

Acquire and releaseacquire, release, release-acquire

A pairing that passes data between threads. A release write publishes every write before it; an acquire read that sees that value is guaranteed to see them too. Release stops earlier accesses moving after it; acquire stops later accesses moving before it.

Java volatile write and read, or VarHandle setRelease and getAcquireC++ store(v, std::memory_order_release) paired with load(std::memory_order_acquire)
See also: Synchronizes-with, Memory order, Safe publication

Actor modelactor, actors

A way to structure concurrency in which each actor has private state and a mailbox, handles one message at a time, and talks to other actors only by sending messages. Many actors can share a pool of threads, but no actor ever runs on two threads at once.

Java a class with private state, a bounded mailbox queue and one consuming thread, or a framework such as AkkaC++ a class with private state, a mutex-guarded mailbox and one consuming std::thread
See also: Single writer principle, Message passing, Keyed executor

Adaptive concurrency limit

A concurrency limit that adjusts itself from observed latency, like TCP congestion control: it grows while latency stays near the no-load baseline and shrinks when latency rises, which signals queueing.

Java Netflix's open source concurrency-limits libraryC++ usually hand written; Envoy's adaptive concurrency filter does it in a proxy
See also: Concurrency limit, Admission control

Adaptive spinningspin-then-park, adaptive mutex, spin-then-block

A lock strategy that spins briefly when the lock is busy, betting that the holder will release it within microseconds, and parks the thread only if the spin fails. It avoids two context switches for short critical sections without burning CPU on long ones.

Java HotSpot monitors spin adaptively before parking; the spin length adapts to recent successC++ glibc offers PTHREAD_MUTEX_ADAPTIVE_NP; std::mutex implementations may spin briefly before a futex wait
See also: Spinlock, Futex, Parking

Address spacevirtual address space

The range of memory addresses a process can use. Each process has its own, mapped onto physical memory by the operating system, which is why one process cannot read another's memory.

Java the JVM's heap, class metadata, compiled code and every thread stack live in one address spaceC++ code, globals, the heap and every thread's stack share one address space
See also: Process, Virtual memory

AddressSanitizerASan

A tool built into clang and gcc that reports memory errors at run time: use after free, buffer overflows and use of a local after its scope ended, with the stacks involved.

Java not needed; the JVM checks bounds and the garbage collector prevents use after freeC++ compile and link with -fsanitize=address; it cannot be combined with ThreadSanitizer in one build
See also: ThreadSanitizer, Dangling reference

Admission control

Deciding at the front door whether to accept a request, before any expensive work, from signals such as in-flight count, queue time, per-client rate or priority. Rejected requests get a fast 429 or 503.

Java a semaphore and per-client token buckets checked in a request filterC++ the same checks before a request is queued for a worker
See also: Load shedding, Concurrency limit, Back-pressure

Aging

Raising the effective priority of waiting work the longer it waits, so low priority work cannot be postponed forever by a steady stream of higher priority work.

Java order a PriorityBlockingQueue by enqueue time minus a priority bonus instead of by priority aloneC++ the same comparator on a std::priority_queue guarded by a std::mutex
See also: Starvation, Fair lock

Aliasing

Two or more references that point to the same object. Each alias is another way to reach the object, so an alias held by another thread turns the object into shared state.

Java passing an object to a thread, a lambda, a queue or a static field creates an aliasC++ two pointers or references to one object; the same sharing rules apply
See also: Reference, Data race

Amdahl's law

If a fraction s of the work is serial, N threads speed it up at most 1 / (s + (1 - s) / N) times, and never more than 1 / s times however many threads you add.

Java time spent inside one global lock counts as serial workC++ the same
See also: Lock contention

Amortized cost

The average cost per operation over a long sequence in which a few operations are expensive. Appending to a growable array is amortized O(1) even though an occasional resize copies everything.

Java ArrayList.add and ArrayDeque.addLast are amortized O(1)C++ std::vector::push_back is amortized O(1)
See also: Binary heap

As-if rule

The compiler may transform a program in any way that keeps the observable behavior of a correct program. It assumes there is no undefined behavior, which is why a data race lets it hoist, merge or delete memory accesses.

Java the JIT has the same freedom within the rules of the Java memory modelC++ a loop on a plain bool flag may be compiled to read the flag once
See also: Undefined behavior, Data race

At-least-once delivery

Retry until the receiver acknowledges: nothing is lost, but a message can arrive more than once, so receivers must be idempotent.

Java process, then commit the Kafka offset; a crash in between means redeliveryC++ the same with librdkafka or any queue client
See also: At-most-once delivery, Idempotent consumer, Exactly-once

At-most-once delivery

Send a message once and never retry: it may be lost but is never duplicated.

Java commit the consumer offset before processing, or fire and forgetC++ the same
See also: At-least-once delivery, Exactly-once

Atomic array

An array exposing atomic operations and visibility guarantees for each element separately. Several element accesses do not form one atomic transaction or consistent whole-array snapshot.

Java AtomicIntegerArray, AtomicLongArray and AtomicReferenceArrayC++ an array of std::atomic elements; choose memory ordering for the protocol
See also: Atomic variable, Compare-and-swap

Atomic field updaterAtomicIntegerFieldUpdater, AtomicLongFieldUpdater, AtomicReferenceFieldUpdater

A reflection based helper that performs atomic operations such as compareAndSet directly on a volatile field of many objects, saving the memory and the extra pointer of an AtomicInteger object per instance. VarHandle is the modern replacement.

Java AtomicIntegerFieldUpdater.newUpdater(Node.class, "state"), or a VarHandle from MethodHandles.lookup().findVarHandleC++ not needed, because a std::atomic member is stored inline; std::atomic_ref gives atomic access to a plain member
See also: VarHandle, Atomic variable, Compare-and-swap

Atomic variableatomics

A variable whose reads, writes and read-modify-write operations are indivisible and properly ordered between threads.

Java AtomicInteger, AtomicLong, AtomicReference, LongAdderC++ std::atomic<T>
See also: Compare-and-swap, Atomicity

Atomicityatomic

A group of steps happens as one indivisible step: no other thread can see it half done or slip in between.

Java synchronized blocks, atomic classes, ConcurrentHashMap.computeC++ a std::mutex held across the steps, std::atomic operations
See also: Critical section, Atomic variable

AtomicMarkableReferencemarkable reference

A Java holder that atomically stores a reference and a boolean mark, often used for logical deletion. Conditional replacement compares reference identity and the mark. Reusing the same reference and mark can still admit ABA.

Java get(boolean[] holder) reads a matching pair; compareAndSet(expectedRef, newRef, expectedMark, newMark) conditionally replaces bothC++ a tagged pointer or atomic aggregate can represent a related scheme, subject to representation and platform atomicity support
See also: AtomicStampedReference, ABA problem, Compare-and-swap

AtomicStampedReferencestamped reference

A Java holder that atomically stores a reference together with an integer stamp. Conditional replacement compares reference identity and the stamp, allowing a version protocol to reject stale operations after ABA.

Java get(int[] holder) reads a matching pair; compareAndSet(expectedRef, newRef, expectedStamp, newStamp) replaces it conditionally; writers manage stamp changesC++ a tagged pointer or versioned atomic state provides a related technique, subject to representation and platform atomicity support
See also: ABA problem, Compare-and-swap, Atomic variable

Autoboxingboxing, unboxing

Automatic conversion between a primitive and its wrapper object, such as int and Integer. Boxing allocates or reuses an object; unboxing a null reference throws NullPointerException.

Java Integer x = 5 calls Integer.valueOf(5); int y = map.get(k) throws if the key is absentC++ no equivalent; values stay values
See also: Integer cache

B

Back-pressureback pressure, backpressure

Pushing a slowdown upstream: when a consumer cannot keep up, its full buffer makes producers block, slow down or get rejected, instead of letting work pile up without limit.

Java a bounded BlockingQueue: put blocks, offer with a timeout gives upC++ a bounded buffer whose put waits on a condition variable, or a try_put that returns false
See also: Bounded buffer, Producer-consumer

Backoff and jitterexponential backoff, jitter

After a failed attempt, wait before retrying, usually doubling the wait each time (exponential backoff) and adding randomness (jitter) so that competing threads stop retrying in lockstep.

Java Thread.sleep or LockSupport.parkNanos with a delay from ThreadLocalRandom.current().nextLong(bound)C++ std::this_thread::sleep_for with a delay from a std::uniform_int_distribution over a growing range
See also: Livelock, tryLock

Banker's algorithm

Dijkstra's deadlock avoidance algorithm: every thread declares its maximum need, and a request is granted only if, after granting it, some order still exists in which every thread can get its maximum and finish.

Java rarely used in application code; an operating systems and online assessment classicC++ the same
See also: Safe state, Deadlock, Resource allocation graph

Barging

When a lock is released, a thread that has just arrived may take it ahead of threads already queued. Unfair, but fast, because the lock goes to a thread that is already running.

Java the default ReentrantLock and synchronized; tryLock() barges even on a fair ReentrantLockC++ typical std::mutex implementations allow it
See also: Fair lock, Lock convoy

Barriercyclic barrier, CyclicBarrier, std::barrier

A reusable meeting point for a fixed group of threads: each thread waits until all have arrived, an optional action runs once, then all continue into the next phase.

Java java.util.concurrent.CyclicBarrier with a barrier action; BrokenBarrierException when a party failsC++ std::barrier (C++20) with a noexcept completion function, arrive_and_wait, arrive and arrive_and_drop
See also: Latch, Phaser, Generation counter

Batchingbatch processing

Paying a large fixed cost, such as a flush, a network round trip or a system call, once for many items instead of once per item. Batches are usually cut at B items or T milliseconds, whichever comes first, so latency stays bounded when traffic is light.

Java take one item, then drainTo up to B minus 1 more, or poll with the time left until the deadlineC++ wait for the first item, then wait_until a deadline for more, and pop up to B under one lock
See also: Group commit, Pipeline, Single writer principle

Biased locking

An old HotSpot optimization that let one thread lock the same object again and again with no atomic instruction. It was disabled by default in JDK 15 and later removed, so Java 21 does not have it.

Java Java 21 rejects the old UseBiasedLocking flag as unrecognizedC++ no equivalent
See also: Thin and inflated locks

Binary heappriority queue

A tree stored in an array in which every parent is no larger than its children. It gives O(log n) insert and remove of the smallest element and O(1) peek, but its iteration order is not sorted.

Java PriorityQueue; PriorityBlockingQueue and DelayQueue for use between threadsC++ std::priority_queue, a max heap by default
See also: Amortized cost

Binary semaphore

A semaphore whose count is only 0 or 1. Unlike a mutex it has no owner: any thread may release it, which makes it a signal between threads rather than a lock.

Java new Semaphore(1); Java does not cap it, so an extra release makes two permitsC++ std::binary_semaphore (C++20); releasing when the count is already 1 is undefined behavior
See also: Semaphore, Mutex

Blockingblocked thread, blocking call

A thread stopping until something happens: a lock comes free, data arrives, a signal is sent or time passes. A blocked thread uses no CPU, but it keeps its stack and everything it holds: locks, connections, permits.

Java entering a busy synchronized block (BLOCKED), wait, join, sleep, Lock.lock, BlockingQueue.take, socket readsC++ std::mutex::lock, condition variable waits, join, sleep_for, blocking reads
See also: Parking, Thread states, Busy waiting

Blocking queueBlockingQueue

A thread-safe queue whose take waits while it is empty and, when it has a capacity, whose put waits while it is full. The hand-off also makes the producer's earlier writes visible to the consumer.

Java java.util.concurrent.BlockingQueue: ArrayBlockingQueue, LinkedBlockingQueue, SynchronousQueue, PriorityBlockingQueue, DelayQueue, LinkedTransferQueueC++ none in the standard library; build one from a std::mutex, two std::condition_variable objects and a std::deque
See also: Producer-consumer, Back-pressure, Two-lock queue, Poison pill

Bounded bufferbounded queue, bounded blocking queue

A queue with a fixed capacity: put blocks (or fails) while it is full and take blocks while it is empty. The capacity is what turns a slow consumer into back-pressure instead of unbounded memory growth.

Java ArrayBlockingQueue, LinkedBlockingQueue with a capacityC++ write it yourself: a mutex, a deque and two condition variables, or a ring buffer over a fixed array
See also: Producer-consumer, Back-pressure

Bounded type parameter

A type parameter restricted to subtypes of some type, so that generic code may call that type's methods.

Java <T extends Comparable<? super T>> lets a priority queue compare its elementsC++ C++20 concepts and requires clauses, for example template <std::totally_ordered T>
See also: Wildcard type, Type erasure

Bounded waiting

The guarantee that a waiting thread gets in after at most a fixed number of other threads get in ahead of it. First come, first served gives the tightest bound: you wait only for those who arrived before you.

Java fair locks and ticket based monitors; new ReentrantLock(true)C++ ticket based monitors or ticket locks; std::mutex promises nothing
See also: Starvation, Fair lock, Ticket lock

Broken barrierBrokenBarrierException

The state a Java CyclicBarrier enters when a waiting party is interrupted or times out, or the barrier action throws: every other waiter, and every later arrival, fails with BrokenBarrierException instead of waiting forever for a party that has left.

Java CyclicBarrier.isBroken(), reset() to start a new generation, BrokenBarrierException thrown from await()C++ std::barrier has no broken state; a participant that cannot continue must call arrive_and_drop()
See also: Barrier, Generation counter, Interruption

Buddy allocatorbuddy system, binary buddy allocation

A memory allocator that manages power-of-two blocks with one free list per size. Allocation splits a larger block into two halves (buddies) until the size fits; freeing merges a block with its buddy, found with offset XOR size, whenever that buddy is free. It is fast and coalesces cheaply, at the cost of up to about half a block of internal fragmentation.

Java rarely written in Java; the idea appears in off-heap buffer poolsC++ an array of free lists indexed by order, a per-block order and free bit, and one mutex (or per-thread caches in front)
See also: Free list, Fragmentation

Builder patternbuilder

Accumulate construction inputs, validate the complete combination, then produce a finished object. Confine mutable builders and avoid sharing mutable construction state with the product.

Java A nested Builder with a build method and defensive copies in the product.C++ A builder whose build method returns a completed value or owning pointer.
See also: Simple factory, Safe publication

Bulkheadresource isolation, separate pools

Giving each kind of work its own bounded pool of threads or connections, so that one kind cannot use up the resource another kind needs, the way watertight compartments keep a ship afloat when one floods.

Java one ExecutorService per kind of task or per downstream dependencyC++ one thread pool per kind of task, each with its own queue and workers
See also: Thread starvation deadlock, Back-pressure

Busy waitingspinning, spin-wait

Waiting by checking a condition again and again in a loop instead of sleeping. It reacts fast but burns a whole core, and can slow down the very thread it is waiting for.

Java while (!done) Thread.onSpinWait(); the flag must be volatile or atomicC++ while (!done.load()) {}; the flag must be a std::atomic
See also: Spinlock, Spin-wait hint, Condition variable

Bytecode

The portable instruction set that javac writes into .class files. One source line often becomes several bytecodes: a field increment is a separate load, add and store.

Java inspect it with javap -c; count += 1 on a static int is getstatic, iconst_1, iadd, putstaticC++ no equivalent; C++ compiles straight to machine code for one target
See also: JVM, Read-modify-write

C

C++ spanstd::span

A non-owning view of a contiguous range of elements. Copying the view neither copies the elements nor extends their lifetime; backing storage must remain valid throughout access.

C++ std::span<T> from C++20; std::span<const T> prevents writes through the view but does not stop another alias modifying the elements.
See also: String view, Dangling reference

Cache coherenceMESI, coherence protocol

The hardware protocol that keeps every core's cached copy of a line in agreement. Under MESI a line is Modified, Exclusive, Shared or Invalid in each cache, and a core must invalidate other copies before it writes.

Java invisible to code, but it is why contended writes to one line are slowC++ invisible to code, but it is why contended writes to one line are slow
See also: Cache line, False sharing, Store buffer

Cache line

The unit in which memory moves between RAM and CPU caches and between cores. It is 64 bytes on most x86 chips; Apple M series chips report 128 bytes. Two variables in one line travel together.

Java no API for the size; arrays are contiguous, but object field layout is up to the JVMC++ std::hardware_destructive_interference_size (C++17) is the compiler's guess at it
See also: False sharing, Cache coherence

Cache stampededog-pile, dogpile effect

A popular cache entry expires or is evicted, many concurrent requests miss at the same moment, and they all ask the backend for the same value, which can overload it.

Java fixed with single-flight loading, early refresh, serving stale values and jittered TTLsC++ the same fixes; the mechanism does not depend on the language
See also: Single-flight, Thundering herd, Time to live, Serve stale

Caller-runs policyCallerRunsPolicy

A rejection policy where the thread that submitted the task runs it itself when the pool is full. The producer slows down to the pool's pace, a natural backpressure, but it is harmful on threads that must stay responsive, such as acceptor or event loop threads.

Java new ThreadPoolExecutor.CallerRunsPolicy(); after shutdown it silently discards the taskC++ in a hand-built pool's submit: release the lock and call the task directly when the queue is full
See also: Rejection policy, Back-pressure

Carrier thread

A platform thread that runs virtual threads. By default the JVM keeps a ForkJoinPool of carriers, one per core, and a virtual thread is mounted on one while it runs.

Java printing Thread.currentThread() inside a virtual thread names its carrier, for example ForkJoinPool-1-worker-1C++ the closest idea is the thread that runs an executor's or an event loop's tasks
See also: Virtual thread, Pinning

CAS loopcompare-and-swap loop, retry loop, optimistic update

The pattern behind every lock-free update: read the current value, compute the new value from it, compare-and-swap; if the swap fails because another thread changed the value, compute again from the fresh value and retry.

Java while (true) { long cur = x.get(); if (x.compareAndSet(cur, f(cur))) break; } or simply x.updateAndGet(f)C++ long cur = x.load(); while (!x.compare_exchange_weak(cur, f(cur))) {} because a failed CAS refreshes cur
See also: Compare-and-swap, Spurious failure, Lock-free

Change data captureCDC, log tailing

Reading a database's own change log (such as the MySQL binlog or the PostgreSQL write-ahead log) to publish every committed change as an event. It is the low-latency way to relay a transactional outbox without polling the table.

Java Debezium is a widely used open-source CDC tool built on Kafka ConnectC++ usually consumed from a CDC pipeline rather than implemented directly
See also: Transactional outbox, Dual write, Write-ahead log

Check then act

Making a decision on shared state and then acting on it, when the state can change between the check and the act.

Java if (!map.containsKey(k)) map.put(k, v)C++ if (cache.find(k) == cache.end()) cache[k] = load(k)
See also: Race condition, Atomicity

Checked exceptionchecked, throws clause

An exception the compiler makes you handle: the method must catch it or declare it with throws. In Java that is every Exception that is not a RuntimeException.

Java InterruptedException, IOException, TimeoutException and ExecutionException; Runnable.run cannot throw them, Callable.call canC++ no equivalent; C++ never forces callers to handle exceptions, and noexcept only promises that none escape
See also: InterruptedException, try-with-resources, Uncaught exception handler

Circuit breaker

A guard in front of a dependency that stops calling it once failures cross a threshold (open), fails fast during a cool-down, then lets trial calls through (half-open) to decide whether to close again.

Java Resilience4j CircuitBreaker, or a small class with synchronized state transitionsC++ a class with a mutex around the closed, open and half-open transitions and an injectable clock
See also: Bulkhead, Retry budget

Circular waitwait cycle

A cycle of threads in which each holds a lock and waits for a lock held by the next one, the fourth Coffman condition. It is the condition most code breaks, by acquiring locks in one global order so that no chain of waiting can return to its start.

Java five threads each holding fork p and waiting for fork p + 1, as in the dining philosophers; a thread dump shows the cycleC++ two std::lock_guard objects taken in different orders by different threads; std::scoped_lock avoids it for one set of mutexes
See also: Coffman conditions, Lock ordering, Deadlock

Class loading and initializationclass initialization, static initializer

The JVM loads, links and initializes each class lazily, the first time it is actively used. Initialization runs the static initializers exactly once, under a per-class lock, so every thread sees the finished result.

Java static blocks and static field initializers; the lazy holder idiom for singletons relies on this guaranteeC++ a function-local static variable is initialized once, in a thread-safe way, since C++11
See also: JVM, Happens-before

Class template argument deductionCTAD, deduction guide

Since C++17, the compiler can deduce a class template's arguments from the constructor call, so you may write std::lock_guard lock(m) instead of std::lock_guard<std::mutex> lock(m).

Java the diamond operator, new ArrayList<>(), plays a similar role for genericsC++ std::lock_guard lock(m_); std::scoped_lock lock(a, b); std::pair p{1, 2.5}
See also: Template

Client-side locking

Making a compound action on someone else's object atomic by taking the very lock that object uses internally. It only works if you lock exactly the same object, which is easy to get wrong.

Java synchronized (list) { if (!list.contains(x)) list.add(x); } on a Collections.synchronizedListC++ rarely possible, since a class's mutex is private; give the class an atomic operation instead
See also: Check then act, Synchronized wrapper

Coffman conditionsfour conditions for deadlock

The four conditions that must all hold for a deadlock: mutual exclusion, hold and wait, no preemption and circular wait. Break any one of them and deadlock becomes impossible.

Java lock ordering breaks circular wait; tryLock with a timeout breaks no preemptionC++ std::scoped_lock never waits while holding part of its set; lock ordering breaks circular wait
See also: Deadlock, Lock ordering

Command patterncommand object

Represent an action, arguments and receiver as an object so execution can be managed separately from the request. The pattern alone supplies neither thread safety, idempotency nor rollback.

Java Runnable, Callable or a domain command with an execute method.C++ A callable or command object passed to a queue or executor.
See also: Strategy pattern, Observer pattern

Common poolForkJoinPool.commonPool, common fork/join pool

The one ForkJoinPool shared by the whole JVM. It runs every parallel stream and every CompletableFuture async method called without an executor, with a parallelism of available processors minus one, so one blocking task there slows everyone else.

Java ForkJoinPool.commonPool() and ForkJoinPool.getCommonPoolParallelism(); the size can be set with the java.util.concurrent.ForkJoinPool.common.parallelism system propertyC++ no standard equivalent; the parallel algorithms run on a thread pool chosen by the library
See also: Parallel stream, Virtual thread, I/O bound

Compare-and-swapCAS, compare-and-set

An atomic instruction: set the variable to a new value only if it still holds the value you expected, and report whether it did.

Java compareAndSet on the atomic classesC++ compare_exchange_weak and compare_exchange_strong
See also: Atomic variable, Read-modify-write

CompletableFutureCompletionStage

Java's future that can be completed by hand and composed: attach continuations that transform, chain, combine or recover from results without blocking a thread.

Java supplyAsync, thenApply, thenCompose, thenCombine, allOf, anyOf, exceptionally, handle, orTimeout, completeOnTimeoutC++ no standard equivalent in C++20; libraries such as folly provide one, and C++26 std::execution covers composition
See also: Future, Continuation, Common pool

CompletableFuturecompletable future, composable future

Java's future that is also a promise: anyone can complete it once, and you can attach dependent steps (thenApply, thenCompose, thenCombine) that run when it completes instead of blocking on get.

Java CompletableFuture.supplyAsync, complete, completeExceptionally, thenCompose, allOf, orTimeoutC++ no standard equivalent; std::promise and std::future have no continuations, so chaining needs a library or a hand-built future with a callback list
See also: Future, Promise, Executor

Completion serviceExecutorCompletionService, completion order

A wrapper around an executor that hands back finished tasks in the order they complete, not the order they were submitted, so each result can be processed as soon as it is ready.

Java new ExecutorCompletionService<>(pool), then submit tasks and call take() or poll() for the next finished FutureC++ no standard equivalent; have each task push its result into a shared blocking queue
See also: Executor, Future, Blocking queue

Composition

Building an object's behaviour from collaborators it contains rather than inheriting their implementation. The containing object can expose a smaller contract, but must still define ownership and coordinate access to shared mutable collaborators.

Java a bounded inbox owns a private ArrayDeque and exposes atomic offer, poll and snapshot operationsC++ a wrapper keeps its container and mutex as private members and exposes operations that preserve their invariant
See also: Encapsulation, Delegation, Invariant

Concurrency

Several tasks in progress during overlapping periods of time. They may take turns on one core or run at once on many; concurrency is about the structure of a program, not its speed.

Java threads, executors, CompletableFuture, virtual threadsC++ std::thread, std::async, coroutines with an executor library
See also: Parallelism, Event loop

Concurrency limitin-flight limit, max concurrent requests

A cap on how many requests may be in progress at once, usually enforced with a semaphore or a pool size; excess requests wait briefly or fail fast. Unlike a rate limit, it still holds when requests become slow.

Java Semaphore.tryAcquire before the call and release in finally, only after a successful acquireC++ std::counting_semaphore::try_acquire with an RAII guard that releases
See also: Admission control, Adaptive concurrency limit, Bulkhead, Semaphore

ConcurrentHashMapCHM

Java's thread-safe hash map. Since Java 8 it locks per bin: an empty bin is filled with a CAS, a busy bin is locked on its first node, and reads take no lock at all.

Java java.util.concurrent.ConcurrentHashMap; use compute, merge and computeIfAbsent for atomic per-key updates; no null keys or valuesC++ no standard equivalent; stripe your own map or use a library such as oneTBB's concurrent_hash_map
See also: Lock striping, Compare-and-swap

Condition variablecondition

Lets a thread release a lock and sleep until another thread signals that the state it needs may now hold. Always wait in a loop.

Java wait and notifyAll on a monitor, or Condition from a ReentrantLockC++ std::condition_variable with a std::unique_lock and a predicate
See also: Monitor, Spurious wakeup

Consistent hashing

Placing owners and keys on a hash ring so that each key belongs to the next owner clockwise; adding or removing one owner moves only about 1/N of the keys, unlike hash mod N, which moves most of them.

Java a TreeMap from ring position to node, with ceilingEntry for lookupC++ a std::map from ring position to node, with lower_bound for lookup
See also: Sharding, Hot partition

Const correctness

Marking every member function that does not change an object's observable state const, and taking read-only parameters as const references. In C++11 and later, the const functions are also the ones expected to be safe to call from several threads at once.

Java no equivalent keyword; immutability comes from final fields and from not exposing settersC++ std::size_t size() const; void print(const Roster& r); the standard library promises concurrent const calls do not race
See also: Logical constness, mutable

constevalimmediate function

A C++20 specifier declaring an immediate function. An ordinary invocation must produce a constant expression; calls within an immediate-function context can defer this requirement to the enclosing invocation.

Java no direct equivalentC++ consteval int twice(int n) { return 2 * n; } rejects an ordinary call with runtime input
See also: constexpr

constexpr

For a variable, requires a constant-expression initializer and makes the variable const. For a function, permits constant evaluation while also allowing runtime calls; it does not require every call to be evaluated at compile time.

Java static final primitive constants can serve some of the same roles, but there is no constexpr function facilityC++ constexpr int twice(int n) { return 2 * n; } can be called with runtime input or in a static_assert
See also: consteval, Const correctness

Work and spanwork-span model, critical path

Work is the total number of steps a parallel algorithm performs; span is its longest chain of steps that must run one after another. On P cores the running time is at least the larger of work divided by P and span, so the speedup can never exceed work divided by span.

Java parallel merge sort with sequential merges has work O(n log n) and span O(n)C++ the same analysis; a parallel merge shrinks the span to a polylogarithm
See also: Amdahl's law, Fork/join, Sequential cutoff

Work queuetask queue, pool queue

The queue between submitting a task and a worker running it. Whether it is bounded decides what overload looks like: an unbounded queue turns overload into growing latency and memory, a bounded one into rejections or backpressure.

Work stealingwork-stealing scheduler

A scheduling scheme where each worker keeps its own deque of tasks, works from one end, and when idle steals the oldest task from the other end of a busy worker's deque. Load balances itself with little contention.

Write skew

Two transactions read the same facts, each decides from them, and each writes a different row, so together they break a rule each one checked. Snapshot isolation allows it; serializable isolation or locking the rows the rule reads prevents it.

Write-ahead logWAL, redo log, commit log

An append-only log to which every change is written, and made durable with fsync, before it is applied to the main data structures. After a crash, replaying the log restores every acknowledged change; records carry a length and a checksum so a torn tail can be detected and cut off.

Writer preferencewriter-preferring, reader preference

A read-write lock policy: once a writer is waiting, new readers wait behind it, so a stream of readers cannot starve writers. The mirror policy, reader preference, admits readers whenever no writer holds the lock and can starve writers.

Writer starvation
